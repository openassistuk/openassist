# OpenAssist v0.2.0-rc.1 preview

The installation commands below require the published preview assets on the repository's Releases page.

This is the first packaged OpenAssist preview for Linux glibc and macOS, each on x64 and arm64. It includes a private Node runtime and production dependencies, so packaged installations do not require Git, pnpm or system Node. Windows operator installation and automatic updates are outside this preview.

## Install the published preview

After publication, run this on a supported Linux or macOS host:

```bash
curl -fsSL https://raw.githubusercontent.com/openassistuk/openassist/main/install.sh | bash -s -- --channel preview
```

For this exact release, replace `--channel preview` with `--version 0.2.0-rc.1`. Exact-version installations remain pinned. The default installer continues selecting stable releases; publishing this preview does not create a stable release.

The installer verifies the release signature and artifact hashes before executing downloaded application code. It opens guided setup on an interactive terminal. If needed, open a new terminal and run `openassist setup`, then `openassist doctor` and `openassist service health`.

## Existing installations

Source installations keep following their recorded source track unless explicitly migrated. Preview-capable lifecycle clients can inspect and migrate with:

```bash
openassist update --release --channel preview --dry-run
openassist update --release --channel preview
```

Older source installations need to update their source CLI first using their existing supported upgrade path. Never rerun fresh packaged bootstrap over an existing installation. Back up operator state before testing; compatibility checks can block transitions. See [upgrade and rollback](../operations/upgrade-and-rollback.md).

## Preview limits

Linux requires glibc 2.28+ and kernel 4.18+; macOS requires 13.5+. Alpine/musl and Windows operator installations are unsupported. Isolated developer instances are not a sandbox for untrusted code. Application rollback never silently restores an older database.

Automated artifact and service checks do not certify every live provider/channel integration or every existing installation. Report the release version, OS/architecture, installation method and sanitized reproduction steps when reporting an issue. Keep provider credentials, conversations and private signing material out of issue reports.
