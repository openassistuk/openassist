# OpenAssist v0.2.1 stable security patch

OpenAssist 0.2.1 was published on September 30, 2026 from reviewed main `a30ebc18b50a5a4d023f8cf78a7d2b9b1b97f89a` with 16 signed assets and was latest stable at publication. [Publication run 36789528574](https://github.com/openassistuk/openassist/actions/runs/36789528574) passed all native builds, candidate quality/audits, signing and public stable-channel/exact-version installation on Linux/macOS x64/arm64. Both production signatures and asset digests were independently verified. The [release plan](https://github.com/openassistuk/openassist/blob/main/docs/execplans/stable-0.2.1-release.md) preserves separate preparation, merge, publication and verification evidence. The later [v0.2.2 model refresh](v0.2.2.md) is now current stable; these older signed assets remain immutable.

## Security and correctness changes

Resolve Axios 1.20.0 through WhatsApp/Baileys, repairing five high and two moderate dependency advisories involving denial of service, polluted option handling and network controls. Every resolved copy remains covered by patched-version regressions and production/full dependency audits. The mandatory signature, audit, coverage and access controls are unchanged. Existing immutable v0.2.0 and v0.2.0-rc.1 assets retain affected Axios 1.18.0; source fixes alone do not repair packaged installations.

Windows source prerequisite probes and pnpm lifecycle launches execute known native or npm/Corepack entrypoints directly, preserving literal arguments and the selected PATH. An unsupported first `pnpm.cmd` shim or missing selected-PATH pnpm returns an explicit resolution failure; launches stop and readiness reports pnpm as unavailable without a second executable search. This removes Node DEP0190 shell-launch warnings. Linux and macOS remain the first-class operator platforms; Windows remains a quality/source-development platform.

## Installation and update

Fresh installs use the verified stable catalogue. To select this exact patch:

```bash
curl -fsSL https://raw.githubusercontent.com/openassistuk/openassist/main/install.sh | bash -s -- --version 0.2.1
```

For an existing stable, preview, source or exact-version installation, back up configuration, credentials and the database, inspect the plan, then select the stable track explicitly:

```bash
openassist update --release --channel stable --dry-run
openassist update --release --channel stable
openassist doctor
openassist service health
```

Stable follows the latest signed stable release. Exact-version pins otherwise remain pinned; this explicit channel selection changes the saved track. Older source clients must update their CLI through the supported source path first. See [upgrade and rollback](https://github.com/openassistuk/openassist/blob/main/docs/operations/upgrade-and-rollback.md) and [troubleshooting](https://github.com/openassistuk/openassist/blob/main/docs/operations/common-troubleshooting.md).

## Compatibility and verification limits

The release includes private Node 24.21.0 and supports Linux glibc 2.28+/kernel 4.18+ and macOS 13.5+, each on x64/arm64. Operators need no system Node, Git, pnpm or signing keys. Source development uses Node >=24.21.0 <25 and pnpm 12.5.1. Alpine/musl and Windows operator installation remain unsupported.

Database compatibility remains version 1, with `managed-one-shots-v1` retained. Updates preserve operator state; application rollback never silently restores databases. Rollback to rc.1 remains blocked while one-shot work is nonterminal. Configuration/provider/channel contracts and access profiles are unchanged.

All four native builds, signing contracts and exact-head quality/security checks passed. Protected publication additionally passed all four public stable-channel/exact-version installs, data-preserving uninstall and independent production-signature verification. These gates do not certify live provider/channel sessions; replacement-host and second-account testing remain unverified. The optional upstream `audio-decode` rename deprecation remains visible pending a validated migration; dependency warnings are not suppressed.

Report version, OS/architecture and sanitized reproduction steps. Keep credentials, private conversations and signing material out of reports.
