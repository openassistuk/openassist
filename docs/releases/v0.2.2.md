# OpenAssist v0.2.2 stable model refresh

OpenAssist 0.2.2 refreshes the complete supported OpenAI and Anthropic conversational catalogs and recommends GPT-6.1 Sol with xhigh reasoning for fresh OpenAI/Codex setup, and Claude Opus 5.5 for Anthropic. Existing installations retain saved model IDs and tuning. The [release plan](https://github.com/openassistuk/openassist/blob/main/docs/execplans/stable-0.2.2-release.md) records candidate checks, required review, exact merged-main security checks, protected signing and public installation separately. Preparation alone does not make this version available; consult the release evidence before selecting an exact version.

## Changes since 0.2.1

- Audit all 27 current general-purpose OpenAI model families and 14 active Claude entries, including exact aliases and verified API snapshot pins. Add missing GPT-5.5/Pro, GPT-5.4 Nano/Pro, other Responses-only Pro variants, the GPT-5.6 alias, restricted Daybreak transport, Claude Fable/Mythos 5 and Opus 4.7/4.8. Invitation-only access remains account-dependent; specialized audio/image/realtime products are not assistant model selections.
- Suggest GPT-6.1 Sol with xhigh on fresh OpenAI/Codex setup. Use Responses for its tool calls and preserve bounded reasoning replay. Xhigh can increase reasoning-token cost and latency; operators can choose another supported effort.
- Recommend Opus 5.5 for complex autonomous work. Sonnet 5.5 remains available with supported adaptive thinking; the recommendation is not a claim of a new live comparative benchmark. Keep signed thinking/tool history bounded and preserve compatible manual thinking budgets on older models.
- Correct exact reasoning, sampling, thinking-effort and output-token limits, including legacy minimal effort, Claude Opus 4.5 and Opus/Sonnet 4.6. Surface announced deprecations and block retired requests/readiness with explicit repair guidance rather than rewriting saved IDs.
- Preserve Azure deployment names, endpoint flavors and API-key/Entra authentication. Optional underlying-model hints use verified Azure controls; OpenAI API retirement dates do not retire Azure deployments. Generic OpenAI-compatible setup requires the backend's actual served model ID, with corrected OpenClaw import classification and actionable missing-model guidance.
- Require successful Linux/macOS/Windows CI and full main-branch CodeQL for the exact tagged commit before production signing. Recheck after protected approval; missing, pending, failed or skipped evidence blocks publication. Existing-publication verification and PR artifact checks retain their separate behavior. Make the quickstart wildcard-address health-URL regression independent of host port availability while preserving real occupied-port validation.

See the [model compatibility matrix](https://github.com/openassistuk/openassist/blob/main/docs/providers/model-compatibility.md) for route-specific controls and retirement dates, and the [changelog](https://github.com/openassistuk/openassist/blob/main/CHANGELOG.md) for the complete version history.

## Installation and update

After signed publication, fresh installs use the stable catalogue. To select this exact version on a supported Linux or macOS host:

```bash
curl -fsSL https://raw.githubusercontent.com/openassistuk/openassist/main/install.sh | bash -s -- --version 0.2.2
```

For an existing stable, preview, source or exact-version installation, back up configuration, credentials and the database, inspect the plan, then explicitly select stable:

```bash
openassist update --release --channel stable --dry-run
openassist update --release --channel stable
openassist doctor
openassist service health
```

Stable follows the latest signed stable release. For an exact pin after publication, use `openassist update --version 0.2.2 --dry-run`, then `openassist update --version 0.2.2`. Exact pins otherwise remain pinned until the track is explicitly changed. Older source clients must update their CLI through the supported source path first. See [upgrade and rollback](https://github.com/openassistuk/openassist/blob/main/docs/operations/upgrade-and-rollback.md).

Updating keeps existing model IDs and reasoning/thinking settings. To adopt the fresh defaults or repair a retired model, run `openassist setup wizard`, explicitly select a supported model and compatible tuning, and complete its post-save checks. Quickstart offers an explicit reset or another model when saved Anthropic thinking settings conflict with a selection.

## Compatibility and verification limits

Packages retain private Node 24.21.0 and support Linux glibc 2.28+/kernel 4.18+ and macOS 13.5+, each on x64/arm64. Operators need no system Node, Git, pnpm or signing keys. Source development requires Node >=24.21.0 <25 and pnpm 12.5.1. Alpine/musl and Windows operator installation remain unsupported.

Database compatibility remains version 1 with `managed-one-shots-v1`. Updates preserve operator state; application rollback never silently restores databases. Rollback to rc.1 remains blocked while one-shot work is nonterminal. Tool-loop limits, context bounds, access profiles and secret redaction remain unchanged. The Axios security repair from 0.2.1 and unchanged dependency-audit/coverage gates are retained.

Local and PR results, merged-main CI/CodeQL, four native packages, signing contracts, protected publication, public installation/removal and independent production-signature verification require their own recorded evidence. These checks do not certify live provider/channel performance; fresh-host and second-account sessions remain unverified. No new paid provider comparison was run. The optional upstream `audio-decode` rename deprecation remains visible pending a validated migration.
