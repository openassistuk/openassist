# OpenAssist v0.2.3 security and maintenance patch

OpenAssist 0.2.3 packages the merged WhatsApp media-security repairs, routine SDK/logging updates and CI/workflow-lint fixes since 0.2.2. This release is prepared but not published. Current public stable remains [v0.2.2](https://github.com/openassistuk/openassist/releases/tag/v0.2.2) until the [release plan](https://github.com/openassistuk/openassist/blob/main/docs/execplans/stable-0.2.3-release.md) records reviewed-main checks, protected production signing and successful public verification.

## Changes since 0.2.2

- Resolve WhatsApp/Baileys media dependencies to Sharp `0.35.5` with bundled librsvg `2.63.2`, and music-metadata `11.16.0`. Remove the affected versions behind one high SVG-decoder memory-safety report and five moderate metadata-parser reports. Upstream describes possible SVG code execution under specified Linux/glibc conditions; no OpenAssist exploit is asserted. Lockfile floors, actual native-library checks and bounded malformed APEv2 regressions preserve normal thumbnail/audio behavior without weakening audit gates. See [the media repair evidence](https://github.com/openassistuk/openassist/blob/main/docs/execplans/ci-whatsapp-media-audit-2026-10-10.md).
- Refresh OpenAI SDK `7.27.0`, Anthropic SDK `0.131.0`, Pino `10.4.0`, paired Vitest/coverage-v8 `5.0.3`, Luxon types `3.7.6` and Node types `24.19.1`. Preserve existing model catalogs, request/auth/replay contracts and configured logger redaction; new vendor SDK helpers do not become new OpenAssist tools or model choices automatically.
- Resolve development-only source-map-js to `1.2.2` for indexed source-map event-loop denial of service. Remove the unused actionlint CLI glob dependency tree affected by an unpatched braces advisory; workflow lint retains the bundled WASM library API and Node globbing.
- Reject unmatched workflow-lint targets, inspect the same actual files for syntax/action policy, preserve literal native/Docker option operands and default targets, and enforce the exact documented Vitest coverage scope. Retain Linux/macOS/Windows quality, coverage and production/full audit gates.

See the [changelog](https://github.com/openassistuk/openassist/blob/main/CHANGELOG.md) for dated changes and separate source-repair evidence. Existing signed tags/assets remain immutable.

## Installation and update after publication

The commands in this section select 0.2.3 only after it is signed, published and publicly verified. Until then, stable selects 0.2.2 and an unavailable exact version fails clearly without falling back to source or unsigned downloads.

For a fresh supported Linux or macOS host, select the new exact version after publication:

```bash
curl -fsSL https://raw.githubusercontent.com/openassistuk/openassist/main/install.sh | bash -s -- --version 0.2.3
```

For an existing installation, back up configuration, credentials and the database, inspect the plan, then explicitly select stable:

```bash
openassist update --release --channel stable --dry-run
openassist update --release --channel stable
openassist doctor
openassist service health
```

For an exact pin, use `openassist update --version 0.2.3 --dry-run`, then `openassist update --version 0.2.3`. Existing exact pins otherwise stay pinned until explicitly changed. Older source clients must update their CLI through the supported source path first. See [upgrade and rollback](https://github.com/openassistuk/openassist/blob/main/docs/operations/upgrade-and-rollback.md).

Updates preserve saved model IDs, provider tuning and operator state. Use `openassist setup wizard` only for deliberate configuration changes or repair. Operators do not supply signing keys; signatures and checksums remain mandatory.

## Compatibility and verification limits

Packages retain private Node `24.21.0` and support Linux glibc 2.28+/kernel 4.18+ and macOS 13.5+, each on x64 and arm64. Packaged operators need no system Node, Git or pnpm. Source development requires Node `>=24.21.0 <25` and pnpm `12.5.1`. Alpine/musl and Windows operator installation remain unsupported.

Database compatibility remains version 1 with `managed-one-shots-v1`; application rollback never silently restores databases, and rollback to rc.1 remains blocked while one-shot work is nonterminal. Access profiles, tool-loop/context bounds, redaction and build permissions are unchanged. Prior security floors remain enforced.

Preparation must pass the unchanged full local gate and exact-head PR checks. The actual merged release commit needs its own main-branch CI/full CodeQL, four native packages, Linux candidate quality/lifecycle checks and signing contracts before protected production signing. Public availability requires successful stable-channel/exact-version installation and data-preserving uninstall on all four supported targets plus independent production signatures/digest verification. These publication gates are pending at preparation; actual results belong in the living release plan and final PR/release records.

Additional replacement-host and second-account provider/channel sessions remain unverified. Automated media and artifact checks do not certify live WhatsApp/provider performance, and no SVG code-execution exploit or paid provider comparison is run for this patch. The optional upstream audio-decode rename deprecation remains visible pending a validated migration.
