# OpenAssist v0.2.4 Anthropic reliability patch

OpenAssist 0.2.4 packages the Anthropic integration and routine dependency updates merged since 0.2.3. Signed stable [v0.2.4](https://github.com/openassistuk/openassist/releases/tag/v0.2.4) was published at 2026-10-16 15:34:48 UTC from PR #86's reviewed main `78b3e40c2eeed2d921232060efd47b41935b57dc` with sixteen assets. GitHub latest stable selected it until v0.2.5; this earlier tag and its assets remain immutable. The [release plan](https://github.com/openassistuk/openassist/blob/main/docs/execplans/stable-0.2.4-release.md) records exact-main checks, protected signing, independent signatures/digests and four-target public verification.

## Changes since 0.2.3

- Update the official Anthropic TypeScript SDK from the published package's `0.131.0` to `0.135.0`. Translate dotted, Unicode, overlong and reserved-prefix runtime tool names to deterministic API-safe identifiers, then restore canonical names before normal runtime policy/execution/audit checks. OpenAssist keeps its own bounded sequential executor; vendor agent runners and server tools are not enabled.
- Preserve complete assistant tool turns with or without thinking, group matching results and avoid duplicate audit placeholders across restart. New replay is provider/model-scoped, wire-name-versioned and bounded to 1 MiB/256 blocks; legacy replay remains readable. Incomplete turns after interruption fall back to reconciled completed history without retrying unfinished side effects or editing durable audit rows.
- Keep synthetic round-limit/disabled replies free of provider tool-turn metadata. Narrower follow-ups retain completed work and the limit explanation without replaying calls twice; earlier synthetic rows carrying duplicate metadata also retain their ordinary text.
- Add verified `claude-haiku-5-5` choices without changing saved models or the Opus 5.5 recommendation. Haiku defaults to adaptive thinking/medium effort, accepts all five efforts, and permits disabled thinking only at high effort or below. Manual budgets and non-default sampling are rejected. Its output default/maximum is `16384`/`128000`, including thinking; wizard filters incompatible disabled efforts. Adaptive mode uses prefix-binding controls; disabled mode omits those controls and removes opaque thinking from replay while retaining text/tools/results.
- Make configured endpoint, selected API-key/bearer headers and workspace authoritative over ambient SDK overrides. Disable SDK debug logging and automatic OpenTelemetry so request content stays within OpenAssist's existing logging/redaction boundary. The SDK's telemetry dependency does not enable a tracing exporter or new runtime capability.
- Include routine OpenAI SDK `7.31.0`, cron-parser `5.10.2` and Inquirer prompts `8.7.3` updates. Preserve the existing security overrides, build permissions, paired test tooling, coverage thresholds and dependency-audit gates. No dependency refresh beyond the already merged source is introduced by preparation.

See the [changelog](https://github.com/openassistuk/openassist/blob/main/CHANGELOG.md) and [Anthropic evidence](https://github.com/openassistuk/openassist/blob/main/docs/execplans/anthropic-integration-2026-10-16.md). Older signed tags and assets remain immutable.

## Installation and update

Fresh installs and explicit stable updates select published 0.2.4. Existing exact pins stay pinned until explicitly changed. Unavailable versions and signature/checksum failures stop clearly without unsigned or source fallback.

For a fresh supported Linux or macOS host, select this exact version:

```bash
curl -fsSL https://raw.githubusercontent.com/openassistuk/openassist/main/install.sh | bash -s -- --version 0.2.4
```

For an existing installation, back up configuration, credentials and the database, inspect the plan, then explicitly select stable after reviewing the plan:

```bash
openassist update --release --channel stable --dry-run
openassist update --release --channel stable
openassist doctor
openassist service health
```

For an exact pin, use `openassist update --version 0.2.4 --dry-run`, then `openassist update --version 0.2.4`. Existing exact pins otherwise remain pinned. Older source clients must update their CLI through the supported source path first. See [upgrade and rollback](https://github.com/openassistuk/openassist/blob/main/docs/operations/upgrade-and-rollback.md).

## Configuration and replay compatibility

Updates preserve saved model IDs, credentials, compatible tuning and operator state. Select Haiku 5.5 explicitly through `openassist setup wizard`; its controls do not accept inherited manual budgets or disabled xhigh/max. Quickstart offers an explicit reset or another model when saved settings conflict. Compatible older Haiku 4.5 manual budgets retain their meaning.

If an installation relied on `ANTHROPIC_BASE_URL` or custom SDK auth/workspace headers, move the intended endpoint into the provider's `baseUrl` and use the configured API-key env reference and optional `workspaceId`. Existing configured credentials/env files remain the supported secret path. Ambient SDK debug/tracing switches no longer enable request diagnostics.

No database migration is required: compatibility remains version 1 with `managed-one-shots-v1`. Rollback never silently restores databases. Older adapters cannot interpret newly versioned wire-name replay and retain the original dotted-tool limitation. Before a deliberate rollback, restore compatible model/tuning and use a fresh conversation or matching pre-update state backup, retaining the current audit history separately. See [configuration rollout and rollback](https://github.com/openassistuk/openassist/blob/main/docs/operations/config-rollout-and-rollback.md).

## Platforms and verification limits

Packages retain private Node `24.21.0`; supported operator targets are Linux glibc 2.28+/kernel 4.18+ and macOS 13.5+, each on x64 and arm64. System Node, Git and pnpm are not required for packaged operators. Source development requires Node `>=24.21.0 <25` and pnpm `12.5.1`. Alpine/musl and Windows operator installation remain unsupported. Access profiles, context/tool-round bounds, scheduler durability, signing trust and existing security floors remain unchanged.
