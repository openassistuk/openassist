# OpenAssist v0.2.5 model-aware context release

OpenAssist `0.2.5` is a release candidate for the context engine and recovery fixes merged in PR #88. It is not published yet. Signed [v0.2.4](https://github.com/openassistuk/openassist/releases/tag/v0.2.4) remains public stable and the default installer target. Preparation, exact-main verification, protected publication and public-install validation are separate steps recorded in the [release plan](../execplans/stable-0.2.5-release.md).

## Changes since 0.2.4

- Replace the runtime's eight-message cutoff with coherent history retained until model/operator pressure requires compaction. Keep the complete current request and mandatory guidance. Every provider call, including tool continuations, scheduled prompts and memory sidecars, passes common admission.
- Prepare, freeze, count and send the same mapped payload across OpenAI, Codex, Anthropic, Azure Foundry and compatible endpoints. Accounting includes instructions, tool schemas/arguments/results, admitted images and bounded opaque replay. OpenAI Responses and Anthropic can count natively near the threshold; unavailable counting and other routes use labeled conservative estimates. Provider rejection remains possible and has one persisted smaller-projection repair, separate from auth/rate/output failures.
- Resolve exact dated route/model capacity from the shared catalog, preserving output/thinking settings. Unknown Codex, compatible/custom and uncataloged serving windows use a labeled 24,000-token fallback or an explicitly verified `contextWindowTokens`. Azure requires a cataloged underlying-model hint; deployment names establish no capacity. Wizard exposes advanced input cost caps, output reservation, byte limits and compaction controls; quickstart uses defaults and preserves saved settings.
- Compact older completed segments with revision/range/raw-digest checked SQLite checkpoints. Preserve original messages and tool audits, whole matched tool frames and source references. Historical excerpts disclose omissions; summaries are not semantically lossless or proof of approvals. Failed, cancelled, stale or oversized summaries cannot advance coverage or repeat host actions.
- Recover aggregate large-tool turns, old image backlogs, restored orphan frames and individually oversized stored results through bounded projection/compaction. Foreground recovery permits at most two summary generations before existing finite durable maintenance. Unsafe full payloads are not mapped to compare recovery progress, and final inference must satisfy every byte/token guard.
- Keep permanent actor-memory extraction independent of context checkpoints and its legacy mirror. An absent extraction cursor starts at zero; existing saved cursors remain authoritative. Retained older messages may be conservatively re-examined through bounded, actor-scoped, idempotent extraction. `/status`, `/memory` and doctor surface context limits, counted/estimated occupancy, checkpoints and failures without exposing raw transcripts or credentials.
- Bound raw summary text to 128 KiB UTF-8 before parsing and use linear fence handling, removing the CodeQL-reported regex backtracking path. Apply exact route/model output ceilings and compatible Anthropic caps/budgets to summary generation and validation. Unsupported tuning needs explicit repair rather than automatic resets.

## Budgets and recovery

Default compaction starts at 85% of usable input and targets 60%. Usable input accounts for native capacity, operator cost caps, reserved output and safety headroom. The default summary-source ceiling is 32,768 tokens; the 8,192-token summary ceiling is capped by the selected model and compatible provider tuning. These are upper bounds, not requested token consumption. Model capacity does not establish account entitlement or quota.

The prepared-payload byte cap defaults to 32 MiB and supports 64 KiB through 64 MiB. Raw-source hydration and transactional digest verification have a separate finite allowance of `max(32 MiB, maxRequestBytes)`, hard-bounded at 64 MiB. A 64 KiB wire cap therefore still permits a stored 120 KB tool result to reach bounded excerpting. The byte field is not a total process-memory ceiling. Rows beyond the raw-source allowance and incomplete maintenance without safe progress fail explicitly; the runtime neither skips them nor clips current input. See the [context engine](../architecture/context-engine.md), [config reference](../configuration/config-reference.md#runtimecontext) and [troubleshooting](../operations/common-troubleshooting.md).

The 12-round default tool budget, existing profile/approval boundaries, attachment/replay limits, credential redaction and signing trust remain unchanged. Context maintenance has no host tools and uses the existing finite durable retry path. It cannot regenerate tool output by repeating an action.

## Installation and update after publication

These commands apply after `v0.2.5` has been published and publicly verified. Until then the stable channel selects `v0.2.4`, and exact `0.2.5` assets are unavailable.

```bash
curl -fsSL https://raw.githubusercontent.com/openassistuk/openassist/main/install.sh | bash -s -- --version 0.2.5
```

For an existing packaged installation, back up config and SQLite together before updating:

```bash
openassist update --version 0.2.5 --dry-run
openassist update --version 0.2.5
openassist doctor
openassist service health
```

Operators following stable can use `openassist update --release --channel stable --dry-run` and then `openassist update --release --channel stable` after publication. Existing exact pins remain pinned until explicitly changed. Source installations follow the supported source update path. Inspect `/status` and `/memory` after updating; use `openassist setup wizard` for deliberate budget changes.

## Compatibility and rollback

Saved model IDs, credentials, compatible thinking/output controls, operator identities and state paths are preserved. The additive `context_checkpoints`, `context_compactions` and `context_rejections` tables retain original messages/tool audits at database compatibility version 1. Validated checkpoints mirror into `session_memory` for older readers. Permanent extraction keeps its separate saved cursor; context coverage is not extraction coverage.

Older binaries may ignore new checkpoint tables and return to their shipped retention behavior. Application rollback does not restore databases. If an older binary processes more conversation, restore the matching config/SQLite backup before re-upgrading so newer checkpoints cannot hide that intervening history; retain current audit data separately before any deliberate restoration. See [rollout and rollback](../operations/config-rollout-and-rollback.md). No automatic source-history deletion or database downgrade is introduced.

## Platforms and verification limits

Operator targets remain Linux glibc 2.28+/kernel 4.18+ and macOS 13.5+, each on x64 and arm64. Packages use private Node `24.21.0`; system Node/Git/pnpm are not required. Source development retains Node `>=24.21.0 <25` and pnpm `12.5.1`. Windows quality coverage does not add Windows operator-install parity.

PR #88's actual merge `f32a1e115d5d31e2c28fec1561cdf0c313a0e4aa` passes [main CI 39143902526](https://github.com/openassistuk/openassist/actions/runs/39143902526) and [full CodeQL 39143902610](https://github.com/openassistuk/openassist/actions/runs/39143902610), both attempt 1. Those checks establish the implementation baseline. This preparation candidate requires its own local/hosted checks and reviewed main merge; exact-main `publication-checks`, native/candidate/signing gates, protected production signing, independent signatures/digests and all four public-install targets remain outstanding for v0.2.5. Old tags/assets and the trust anchor are unchanged.

Live provider/account/quota/model-performance tests, paid calls, fresh provider/channel sessions and replacement-host certification remain unverified. Offline regression, hosted artifact checks and a merged PR do not certify them. Preparation changes no operator credential, config, service or test host.
