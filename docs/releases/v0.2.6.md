## Changes since 0.2.5

- Update production Undici to `6.29.1`, follow-redirects to `1.16.2`, Zod to `4.6.7`, and Azure Identity to `4.14.1` with MSAL Node `7.1.2`. These remove audit findings involving TLS validation, credential disclosure and resource exhaustion. Preserve configured API-key/linked-account/Entra authentication, saved models and tuning, provider request/replay contracts and tool policy boundaries.
- Include the seven routine dependency updates proposed in PR #92: Node 24 types `24.19.2`, paired Vitest/coverage-v8 `5.0.5`, Inquirer prompts `8.7.4`, Zod `4.6.7`, Azure Identity (advanced further to its patched parent), and OpenAI SDK `7.43.0`. New vendor APIs or model names do not activate capabilities automatically.
- Patch development Vite to `8.3.3` and scope glob `14.0.2`/minimatch `11.0.1` to c8's test-exclude 8 dependency path. Tests exercise CommonJS loading, synchronous/asynchronous file selection, dotfiles and exclusions. Keep coverage source scope, thresholds, dependency audits and explicit build permissions intact.
- Load the hosted Linux upgrade/rollback test's fixed historical `0.2.0-rc.1` signed metadata directly from approved release assets. This avoids the catalogue request that returned HTTP 403 on October 31. Production-key verification, exact preview/version identity, archive size/digest checks, the real old updater and data-preserving lifecycle checks remain required. Signature, identity and download failures remain fatal; operator update discovery is unchanged.
- Replace the hanging-channel startup test's 500 ms wall-clock assertion with proof that runtime startup completes while channel initialization remains pending. Keep a finite failure deadline and unconditional runtime/database cleanup. Record November 3's macOS hosted-runner acquisition/capacity failure separately; no source change can certify unavailable runner execution.
- Bound source-staging unit-test I/O with a tiny runtime fixture, asserting the actual executable source and private destination instead of copying the whole Node binary within the five-second test. Native hosted lifecycle smoke still exercises real copying/activation. No test deadline or product behavior changes for this repair.
- Migrate the deprecated optional audio-decode dependency to pinned `@audio/decode@4.2.0` using an import alias. A one-line, exact-Baileys-version patch consumes raw channel arrays; a scoped peer compatibility rule permits only this tested replacement. Validate waveform bytes for buffer/file/stream inputs, bounded malformed-audio degradation and lazy MP3/FLAC/Opus/Vorbis WASM loading. Portable artifact smoke checks the deployed graph on each supported architecture. The expanded codec dependency graph stays optional and introduces no build-script permissions, new channel capability or host tool.

## Security scope

The dependency audit identifies affected resolutions, not confirmed exploitation of an OpenAssist deployment. Key upstream advisories include [MSAL endpoint disclosure](https://github.com/advisories/GHSA-xcx6-jx8p-x3h5), [follow-redirects credential handling](https://github.com/advisories/GHSA-mrwp-f3q8-3g9p), [Zod collection limits](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5), [Undici TLS validation](https://github.com/advisories/GHSA-2m5v-pch6-74hx), [Vite editor handling](https://github.com/advisories/GHSA-587h-7wmj-h5pm), [minimatch amplification](https://github.com/advisories/GHSA-g3hv-75wg-m249) and [glob cancellation](https://github.com/advisories/GHSA-3g3m-2fjr-6pw4). Both production and full registry audit reports remain required; registry errors never count as success. Existing installed packages receive no automatic source-tree repair.

## Installation and updates

The default [quickstart](../operations/quickstart-linux-macos.md) installer selects this stable release; use `--version 0.2.6` for an exact pin. Existing packaged installations can back up config/SQLite together and use:

```bash
openassist update --version 0.2.6 --dry-run
openassist update --version 0.2.6
openassist doctor
openassist service health
```

Exact pins remain pinned until explicitly changed. Future stable-channel updates use `openassist update --release --channel stable`; source installations retain their explicit source route. No database/config compatibility version or state layout changes. Application rollback does not restore databases; retain [matching-backup guidance](../operations/config-rollout-and-rollback.md), including the context checkpoint downgrade/re-upgrade limits inherited from 0.2.5.
