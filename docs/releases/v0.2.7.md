# OpenAssist v0.2.7 maintenance release

This candidate collects dependency and build-tool maintenance since signed v0.2.6. Publication is pending: v0.2.6 remains the public stable installer target until exact-main verification, protected signing and all four public installation checks pass. See the [maintenance and release plan](../execplans/maintenance-0.2.7-2026-11-20.md) for dated evidence.

## Changes since 0.2.6

- Advance bundled/CI Node and the enforced source minimum from 24.21.0 to `24.22.3` for upstream [HTTP/TLS security fixes](https://nodejs.org/en/blog/release/v24.22.3), including parser reentrancy, stream/buffer lifetime, TLS session isolation and a remotely reachable TLS server crash. Source operators must update both shell and service Node before upgrading; packaged installs receive the private runtime through the signed application update. Older immutable packages are unchanged.

- Update OpenAI SDK to `7.56.0`, Anthropic SDK to exact `1.6.0`, Discord.js to `14.28.1`, Inquirer prompts to `8.8.0`, Commander to `15.1.0`, tar to `7.5.23` and cron-parser to `5.10.5`. Include PR #94's previously unreleased SDK/prompt/Discord updates. Preserve saved models/tuning, provider credentials, request/replay boundaries, channel permissions and attachment limits. Vendor agent, automation, admin and message-thread helpers remain unused.
- Preserve Anthropic's explicit `anthropic-version: 2023-06-01` for both token counting and inference, despite SDK 1.x changing its default version. Regression checks cover both authentication kinds and conflicting ambient headers, alongside existing telemetry/logging isolation and bounded tool replay. Remove the obsolete supply-chain age exception for SDK 0.135.0; keep the reviewed major update pinned.
- Update paired Vitest/coverage-v8 to `5.1.0` and pnpm to `12.21.0`, synchronizing bootstrap, hosted workflows and current source-development guidance. Retain explicit `allowBuilds`, narrow security overrides, the exact optional decoder patch/alias/peer combination and unchanged audit/coverage gates. Hosted npm installation no longer uses unnecessary `--force`.
- Reconcile historical scheduled failures without hiding them: November 18's development picomatch advisory [GHSA-fc5q-39xc-vjpf](https://github.com/advisories/GHSA-fc5q-39xc-vjpf) was withdrawn that day at 15:38:56 UTC; current production/full audits return zero. November 17's macOS lifecycle request failed to acquire a runner and executed no steps; Linux passed. Fresh candidate checks remain independently required.

## Installation and updates

Use these commands only after verified publication, with a matching config/SQLite backup:

```bash
openassist update --version 0.2.7 --dry-run
openassist update --version 0.2.7
openassist doctor
openassist service health
```

Fresh installs use the default stable installer after publication, or `--version 0.2.7` for an exact pin. Existing pins remain pinned until explicitly changed; stable-channel selection uses `openassist update --release --channel stable`. Source installs retain their explicit source track. No database/config compatibility version, state layout, access profile or model default changes. Application rollback never restores databases; retain [matching-backup guidance](../operations/config-rollout-and-rollback.md).

## Security and verification

Do not dismiss/suppress advisories or lower coverage thresholds. A withdrawn advisory explains historical failures; it is not evidence of a new security fix or exploitation. Source changes do not alter older immutable signed assets. Configured credentials/endpoints/workspaces remain authoritative, SDK telemetry/logging stay disabled, and vendor helpers confer no tool privileges.

Supported operator targets remain Linux glibc/macOS x64/arm64, with private Node `24.22.3`. Source development requires Node `>=24.22.3 <25` and pnpm `12.21.0`; Windows remains a quality-test target. Local, PR, exact-main, protected publication, signature/digest and public-installer evidence must be recorded separately in the plan. Live provider/account/channel and replacement-host certification remain unverified separately.

Candidate source verification on Node 24.22.3 passes 690 Vitest tests/one existing skip and 267 Node tests/six existing platform skips, unchanged coverage gates and zero production/full dependency findings. The runtime implementation also passes four native packages/signing contracts, PR/full-branch CodeQL with zero results, live macOS and Linux/macOS lifecycle E2E. Final preparation-head checks, required review, exact-main checks and public publication/installation remain separate pending gates; refer to the plan and PR #100 validation for the actual final head.
